# План погрузки контейнерного поезда - Java

Java 17+, сборка стандартным javac, сторонние библиотеки не нужны.
Проверено: javac 26.0.2.1 с --release 17; запуск OpenJDK 17.0.20.1.
Перед сборкой проверьте `javac -version` и `java -version`: обе команды должны указывать Java 17 или новее.
На компьютере могут одновременно стоять разные версии. При ошибке UnsupportedClassVersionError используйте полный путь к java.exe из JDK/JRE 17+.

Из каталога src/java в PowerShell:

```powershell
New-Item -ItemType Directory -Force out | Out-Null
$sources = (Get-ChildItem -File *.java).FullName
javac --release 17 -encoding UTF-8 -d out $sources
java '-Dfile.encoding=UTF-8' -cp out Main train_2041.json 2041
java '-Dfile.encoding=UTF-8' -cp out Main train_2041.json 2041 plan.json
```

Из того же каталога в bash:

```bash
mkdir -p out
javac --release 17 -encoding UTF-8 -d out *.java
java -Dfile.encoding=UTF-8 -cp out Main train_2041.json 2041
java -Dfile.encoding=UTF-8 -cp out Main train_2041.json 2041 plan.json
```

Первый аргумент - JSON, второй - номер поезда, третий необязательный - путь сохранения плана.
Пример входных данных: train_2041.json, тот же файл, что в Python-версии КТ2.
Сущности загружаются из organizers, requests, trains, container_types, containers,
platform_models, platforms, train_platforms. Порядок платформ задается order_no.
Выходной JSON содержит load_plan и placements, формат совпадает с КТ2.
Идентификатор и время плана зависят от текущего времени с точностью до минуты.

## Проверки

Тесты без дополнительных библиотек, после сборки основной программы:

```powershell
javac --release 17 -encoding UTF-8 -cp out -d out tests/PlannerTest.java
java '-Dfile.encoding=UTF-8' -cp out PlannerTest train_2041.json
```

В bash те же команды, аргумент -Dfile.encoding=UTF-8 можно не заключать в кавычки.
Ожидается `PASS: 35 checks`. Проверяются границы ДФЭ, ограничения размещения,
валидация, упоры, чтение/запись JSON и контрольные результаты.
Код возврата 0 означает успех; 1 - ошибки аргументов, файла или данных.
После ошибок проверки контейнеров план не формируется и не сохраняется.

## Устройство

Десять сущностей логической модели представлены классами. Неизменяемые простые
сущности оформлены как record: их поля private final, доступ через методы.
Container20 и Container40 переопределяют расчет ДФЭ. Planner работает со списком
LoadRule, реализованным LengthRule и MassRule. PlatformLoad хранит загрузку
отдельной платформы. LoadPlan содержит размещения, итоговые расчеты и представление
для сохранения. Dataset связывает объекты из JSON; Json обслуживает файловый формат;
Main отвечает за аргументы и консольный вывод.

Порядок распределения и ограничения сохранены из КТ2. Это учебная модель:
жадный алгоритм не перебирает сочетания и не гарантирует оптимальный план.
Физическая модель БД, интеграция с системами терминала и промышленная проверка
допустимости схем погрузки относятся к дальнейшему развитию.

Не включайте out/, build/, target/ и *.class в репозиторий или архив.
